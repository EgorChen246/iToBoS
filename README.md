# iToBoS · Skin Lesion Detection

**Сравнение трёх моделей обнаружения кожных образований:** YOLO26s, Faster R-CNN и Deformable DETR.

Проект исследует качество ограничивающих рамок, подсчёт объектов и скорость обработки. Модель не определяет злокачественность и не ставит диагноз.

## Результаты проверки

30 тестовых фотографий · 116 объектов · CPU · IoU ≥ 0,5.

| Показатель | YOLO26s | Faster R-CNN | Deformable DETR |
|---|---:|---:|---:|
| Порог уверенности | 0,11 | 0,74 | 0,43 |
| Precision | 88,9% | 72,3% | 83,8% |
| Recall | 62,1% | 69,8% | 57,8% |
| F1 | 0,731 | 0,711 | 0,684 |
| Средний IoU верных рамок | 0,777 | 0,774 | 0,756 |
| MAE количества | 1,43 | 1,47 | 1,60 |
| Точное совпадение количества | 18/30 · 60% | 14/30 · 46,7% | 16/30 · 53,3% |
| Среднее время после первой обработки | 0,31 с | 2,71 с | 6,74 с |

Пороги заранее выбраны на 80 валидационных фото по максимуму F1 и на тесте не менялись. Всего: 3000 обучающих, 80 валидационных и 30 тестовых снимков. Выборка теста небольшая, выводы предварительные.

## Запуск в VS Code

Откройте папку репозитория в VS Code. Локально проверено на Python 3.10.6; доступен файл с точными версиями основных библиотек.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-reproduced.txt
.venv\Scripts\python.exe main.py check
```

В VS Code выберите `.venv` как интерпретатор Python и ядро `experiments.ipynb`. Для ноутбука установите расширения Python и Jupyter.

### Данные и веса

Изображения, разметка, веса и старые архивы не публикуются. Их нужно разместить локально:

```text
data/{train,val,test}/images/*.{jpg,png,...}
data/{train,val,test}/labels/*.txt
models/yolo26s.pt
models/fasterrcnn.pth
models/deformable_detr/best_model.pt
models/deformable_detr/config.json
models/deformable_detr/preprocessor_config.json
```

Разметка: один класс `0`, формат YOLO `class x_center y_center width height`, координаты нормированы. Для каждого изображения необходим одноимённый файл разметки, в том числе пустой для фото без объектов. Конфигурация и processor должны соответствовать сохранённой Deformable DETR.

```powershell
# Одно изображение, CPU
.venv\Scripts\python.exe main.py predict --model yolo26s --split val --limit 1

# Повторить тест трёх моделей с зафиксированными порогами
.venv\Scripts\python.exe final_test.py
```

`final_test.py` сохраняет результаты в `results/final_test/`. Повторный запуск перезаписывает результаты предыдущего запуска в этой папке. Загрузчик также поддерживает архивные YOLOv8s и D-FINE-S, но они не входят в текущее сравнение.

## Как читать метрики

- **Precision / Recall:** сопоставление рамок один к одному при IoU ≥ 0,5.
- **IoU:** среднее только для правильно сопоставленных рамок; пропуски отражает Recall.
- **MAE:** средняя абсолютная разница количества предсказанных и размеченных объектов на фото.
- **Точное количество:** доля фото, где количество совпало; расположение рамок оценивается отдельно.
- **Время CPU:** чтение фото, подготовка, обнаружение и обработка результата после первой обработки. Без загрузки модели и сети. Это не время запроса в готовом сервисе.

Результаты времени повторно измерены с выбранными порогами. Первый запрос и загрузка модели приведены отдельно в отчёте. Разные архитектуры используют разные стандартные преобразования размера: YOLO — `imgsz=896`, Faster R-CNN — `min_size=800/max_size=1333`, DETR — сохранённый processor. Значения скорости зависят от среды и нагрузки компьютера.

## Ограничения

Точных файловых дублей между train/val/test не найдено; похожие снимки и пересечения по пациентам отдельно не проверялись. Не подтверждено, что тест не использовался в более ранних экспериментах. Результаты не изолируют влияние архитектуры от истории обучения и данных.

Текущий датасет не проходил отдельный отбор для смартфонного сценария. Для дальнейшего дообучения нужны обычные RGB-фотографии подходящего происхождения; дерматоскопические снимки следует исключить. Происхождение и права на данные проверяются отдельно.

AP из предсказаний, уже отфильтрованных рабочим порогом, не используется в итоговой таблице. Для полноценного AP нужен отдельный прогон с низким порогом сохранения обнаружений.


## Проверка улучшений

Добавлена опциональная обработка пересекающихся рамок и подбор параметров только на валидации. Эффект небольшой: у DETR F1 0,5419 → 0,5459, без роста Recall; исходные результаты теста выше сохранены.

[Разбор ошибок и кандидатов](results/improvement_analysis.md) · [Результаты подбора](results/validation_postprocessing.json)

```powershell
python tune_postprocessing.py --predictions predictions/deformable_detr_val.json
python main.py evaluate --split val --predictions predictions/deformable_detr_val.json --threshold 0.43 --post-nms-iou 0.3
python -m unittest test_postprocess.py
```

Дополнительная NMS не включается автоматически. `--post-nms-iou` используется для оценки сохранённых обнаружений; прежние замеры скорости её не включают.
